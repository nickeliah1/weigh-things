# Weigh Things

Relay an original Withings WBS01's HTTP traffic to Withings and copy the weight from each weigh-in to Garmin Connect. Withings supplies the scale's real profile, clock, and session responses so its normal display can work as it does when connected directly. Firmware 77 sends weight as measurement type `1`, in kilograms after applying its decimal exponent.

## Set up

1. Start Docker and copy the sample configuration.

   ```sh
   cp .env.example .env
   ```

2. Set `SCALE_TIMEZONE` to your local IANA time zone. The bridge resolves the public IP for `scalews.withings.net` through Cloudflare DNS over HTTPS at startup, bypassing the UniFi DNS override. Restart the bridge to pick up an upstream IP change.

   If every weigh-in on the scale is yours, set `SCALE_SINGLE_USER=1` and leave `SCALE_USER_ID` empty. For a shared scale, set `SCALE_USER_ID` to your actual Withings user ID and leave `SCALE_SINGLE_USER=0`. Only matching attributed requests are copied to Garmin on a shared scale.

3. Generate a Garmin session by building the image and running the interactive login command.

   ```sh
   docker compose build
   docker compose run --rm bridge login
   ```

   Enter your Garmin email, password, and any MFA code. Put the complete JSON output on one line in your local `.env`, with single quotes around the JSON. The example below is a placeholder. Keep your `.env` private. Git and the Docker build context exclude it.

   ```dotenv
   GARMIN_TOKEN_JSON='{"access_token":"...","refresh_token":"..."}'
   ```

   ```sh
   docker compose -f ../0traefik/compose.yaml up -d
   docker compose up -d
   docker compose logs -f bridge
   ```

   The bridge reads the token JSON at startup and keeps its Garmin session in memory. The container uses a read-only filesystem and has no volumes. Docker administrators can inspect the container environment. If the supplied token stops working after a restart, rerun login to get fresh JSON and recreate the container.

   Garmin's Personal API key is a separate credential. Garmin documents weight reads through the Personal API, with no weigh-in upload endpoint. Use the session JSON generated by the login command for this bridge. [Garmin Personal API reference](https://developer.garmin.com/gc-developer-program/personal/swagger-docs/)

4. In UniFi, create a local DNS Host (A) record for `scalews.withings.net` pointing to the Docker host's reserved LAN IP. The scale must use the resolver serving that record and be able to reach Traefik on TCP port 80. Traefik routes that hostname to the bridge over the shared `traefik` network. [UniFi DNS documentation](https://help.ui.com/hc/en-us/articles/15179064940439-UniFi-DNS-Records-and-Local-Hostnames)
5. Step on and off the scale. Look for `Uploaded weigh-in to Garmin` in the Compose logs, then verify the reading under Weight in Garmin Connect. A second weigh-in lets you check the display after the scale has downloaded its Withings profile.

## Delivery and troubleshooting

The bridge forwards Withings' HTTP status, headers, and body to the scale, then queues eligible weights from successful HTTP exchanges in memory for Garmin. A Garmin failure is logged and leaves the Withings exchange intact. The queue is lost on restart, and repeated scale requests can create duplicate Garmin readings. The bridge keeps no measurement database or files.

For protocol troubleshooting, set `LOG_RAW=1` and rebuild with `docker compose up -d --build`. This logs both the scale request body and the Withings response status and body, up to 64 KiB per body. The logs can contain names, profile details, identifiers, measurements, and session values. Redact those before sharing and turn raw logging off when finished. Set `SCALE_CAPTURE=1` if you also want to pause Garmin uploads while continuing to relay requests to Withings. If the relay loses connectivity to Withings, restart it to refresh the public address.

To restore the original network path, remove the UniFi DNS override and run `docker compose down`.
